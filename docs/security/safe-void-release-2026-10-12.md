# Safe receipt VOID release ? 12 October 2026

Reception requests cancellation with a reason. An enabled owner or a manager with current clinic correction_approval permission reviews it. Pending/rejected/cancelled requests leave financial rows unchanged. Approval atomically cancels linked payments and allocations (including Cash, Card, Tabby, Tamara and splits), fees, balance payments and outstanding balances, restores applied credit by excluding its original debit, and excludes completed refunds from corrected accounting. No payment-provider request is made.

The original receipt remains VOIDED with its original values. Completed refunds retain their amounts, status and return reference; accounting_void_request_id distinguishes their cancelled report contribution. pos_void_audits and the existing immutable activity log preserve requester, approver, reason, timestamps and original rows. A completed approval retry makes no second reversal. Exact receipt links and existing visit_id links trace plan payments and their legacy mirrors are cancelled; clinical plans/visits and unrelated payments stay intact. Standalone structured plan payments can also be requested from Receipt History.

Migration 20261012171650_safe_receipt_void.sql is separate from all performance work. It checks all original financial/clinical rows before and after the schema changes and aborts if original values change. The updated server adds void_workflow_version=2 after authentication. Older servers keep the previous guarded contract; they cannot activate expanded cancellation with incompatible reports. The wrapped checkout helper is updated to count active credit, preserving its register lock wrapper.

Verification: synthetic PostgreSQL tests cover methods, permissions, disabled/cross-clinic approvers, rejection/cancellation, duplicate requests/approval, credits, prior refunds, stale fingerprints, exact plan links and immutable audits. The actual EOD workbook is exported/reopened as XLSX and checked against the actual CEO/service report routes. UI tests cover success/error feedback, timeout, double click and retry IDs. Earlier native multi-connection tests passed row-lock blocking, stale approval, approve/cancel races and simultaneous requests. The newest explicit balance-collection race test is prepared but was not run because the additional native-test execution was declined. TypeScript and production build passed before release isolation; the isolated VOID package receives a separate final check.

Limits: missing/mismatched credit ledger entries and cancellation that would overdraw already-spent receipt-generated credit require reconciliation. Existing plan_id alone is not evidence that every payment belongs to a receipt; no historical links are guessed or backfilled. Previously exported reports must be regenerated. Actual money remains a separate reconciliation obligation. Receipt 05853 is not voided by applying this migration. No application deployment or main-branch merge is included in this release action.
