# Duplicate treatment-plan correction — 13 October 2026

Reception can request a standalone treatment-plan payment void from both the POS history modal and the paginated history page. When a second plan was created to correct the same payment, the form can select the verified plan/payment to retain. Choices are loaded by a scoped server endpoint, independent of the current history page. A current manager with `correction_approval` permission or an owner approves; the duplicate-plan and money confirmations are separate.

Approval atomically voids the mistaken payment and its linked legacy mirror/allocations, cancels only the identified duplicate plan, and links it to the retained plan with `duplicate_of_plan_id`. Existing clinical visits remain unchanged. Original plan/payment/visit snapshots are retained in an immutable server-only audit table; the existing immutable void audit and activity log also remain. This is accounting cancellation, not a refund or a provider request. Pending, rejected, cancelled, stale and unauthorized requests do not change financial records.

The paired correction requires the same patient/clinic/treatment/price/visit limit and original business day, a verifiable retained payment for the same settled amount, no other active payments/legacy financial links on the duplicate, and no additional clinical activity beyond its original single saved visit. Imported or used plans require owner reconciliation. Both plans and patient file are locked in the existing writer order. Changes to either plan's recorded activity invalidate approval. Older application versions cannot approve a paired cancellation without the new review marker. Repeat approval produces no additional cancellation/audit.

Balances and reports treat an approved duplicate as an invalid original entry, including regenerated reports for its original day. Current and historical corrected balances exclude its phantom debt. EOD keeps a grey, crossed-out “Voided Plan Payments” sheet with the original values excluded from totals. A later pending void request marks the original day EOD as draft. Thermal and A4 reprints are marked VOIDED. Duplicate clinical rows remain in history but do not count toward active doctor-visit statistics. The retained plan and unrelated patients' records stay intact. Local financial-change signals refresh open history/plan balances across same-browser tabs without resetting clinical note forms; other devices must load fresh data/reopen the screen.
